# CC Switch v3.20.0-fork.1

> This is the first fork release (based on upstream v3.20.0). Headline addition: **Claude aggregate providers** — Claude Code's 5+1 model tiers (default / opus / sonnet / haiku / fable / subagent) can each bind to a **different source provider's model**, and the local proxy routes each request to the right upstream by model-name keyword: opus from vendor A's model, fable from vendor B's model, haiku from another of vendor A's models. The aggregate provider itself holds no credentials; the default tier is required as the fallback for unconfigured tiers and unknown model names; a bound provider's failure returns the original error without cross-tier fallback; usage is attributed to the actual upstream provider. **Zero database migration.**

## What you can do now

- **Create one aggregate provider and let each model tier go to its own upstream**: when adding a Claude provider, tick "Aggregate provider" and, in the tier table, pick a source provider and upstream model name for each of the six tiers (default / opus / sonnet / haiku / fable / subagent). The default tier is required — unconfigured tiers and unknown model names fall back to it. Sources can be any regular provider (official providers and other aggregate providers are excluded, to avoid account-risk and circular references).
- **Switch and it just works, through the local proxy**: switching to an aggregate provider points Claude Code's live config at the local proxy, which classifies the request by model name (`claude-opus-*` / `claude-haiku-*` / …) to its tier, then forwards with the bound provider's credentials and full format-conversion pipeline. Format mixing is supported: under one aggregate provider, the opus tier can go through an Anthropic-format relay while the haiku tier goes through an OpenAI-format relay.
- **Delete a referenced provider with full awareness**: before deleting a regular provider referenced by an aggregate provider, the referencing aggregates and tiers are listed; on confirm, non-default tier bindings are cascaded away automatically, while a default-tier reference blocks the deletion (edit the aggregate provider first).
- **See the aggregation at a glance**: provider cards show an "Aggregate" badge plus a per-tier source summary (e.g. `opus→A · fable→B · haiku→A`).

## Guides

- **Provider management**: the aggregate mode and tier table in the add/edit provider form.
- **Local proxy**: aggregate routing depends on proxy takeover — start the proxy service before switching.
