# CC Switch v3.20.0-fork.1

> これはフォーク初回リリースです（アップストリーム v3.20.0 ベース）。目玉は **Claude アグリゲートプロバイダー**——Claude Code の 5+1 のモデル層（default / opus / sonnet / haiku / fable / subagent）それぞれを**別のプロバイダーの別モデル**に紐付けられ、ローカルプロキシがリクエストのモデル名キーワードで該当するアップストリームへルーティングします。opus は A 社のモデル、fable は B 社のモデル、haiku は A 社の別モデル——という使い分けが可能です。アグリゲートプロバイダー自体は資格情報を持ちません。default 層は必須で、未設定の層・未知のモデル名はそこへフォールバックします。紐付いたプロバイダーの失敗は元のエラーをそのまま返し、層をまたぐフォールバックはしません。使用量は実際のアップストリームプロバイダーに帰属します。**データベースマイグレーションなし**。

## できるようになること

- **1 つのアグリゲートプロバイダーで、モデル層ごとに別々のアップストリームへ**：Claude プロバイダー追加時に「アグリゲートプロバイダー」を選択し、層テーブルで 6 層（default / opus / sonnet / haiku / fable / subagent）それぞれのソースプロバイダーとアップストリームモデル名を指定します。default 層は必須——未設定の層と未知のモデル名はそこにフォールバックします。ソースには通常のプロバイダーを指定できます（アカウントリスクと循環参照を避けるため、公式プロバイダーと他のアグリゲートプロバイダーは除外）。
- **切り替えるだけ。あとはローカルプロキシが処理**：アグリゲートプロバイダーへの切り替えで、Claude Code の live 設定がローカルプロキシを向き、プロキシがリクエストのモデル名（`claude-opus-*` / `claude-haiku-*` など）を層に分類し、紐付いたプロバイダーの資格情報とフォーマット変換パイプラインで転送します。フォーマット混在も対応：同一アグリゲートの下で opus 層は Anthropic 形式の中継、haiku 層は OpenAI 形式の中継、といった構成が可能です。
- **参照されているプロバイダーを削除するときも把握できる**：アグリゲートプロバイダーから参照されている通常プロバイダーを削除する前に、参照元と層が一覧表示されます。確認後は非 default 層の紐付けだけが自動で解除され、default 層の参照がある場合は削除がブロックされます（先にアグリゲートプロバイダーを編集してください）。
- **集約構成をひと目で**：プロバイダーカードに「集約」バッジと層別ソース概要（例：`opus→A · fable→B · haiku→A`）が表示されます。

## ガイド

- **プロバイダー管理**：追加/編集フォームのアグリゲートモードと層テーブル。
- **ローカルプロキシ**：アグリゲートのルーティングはプロキシの接管に依存します。切り替え前にプロキシサービスを起動してください。
