# CC Switch v3.20.0-fork.1

> 本版本是 fork 首发版（基于上游 v3.20.0），核心新增：**Claude 聚合供应商**——Claude Code 的 5+1 个模型档（default / opus / sonnet / haiku / fable / subagent）可以分别绑定**不同供应商**的不同模型，本地代理按请求模型名自动路由到对应上游：opus 走甲家的模型、fable 走乙家的模型、haiku 走甲家另一模型。聚合供应商本身不持有任何凭证，默认档必填作为兜底；绑定供应商失败时直接返回原始错误，不跨档回退；用量按实际上游供应商归因。**零数据库迁移**。

## 重点内容：你现在可以

- **创建一个聚合供应商，让每个模型档各走各的上游**：添加 Claude 供应商时勾选「聚合供应商」，在档位表格里为 default / opus / sonnet / haiku / fable / subagent 六档分别选择来源供应商并填写上游模型名。default 档必填——未配置的档位与未知模型名都会回退到它。来源供应商可以是任意普通供应商（排除官方供应商与其他聚合供应商，防止账号风险与循环引用）。
- **切换即生效，全程经过本地代理**：切换到聚合供应商时，Claude Code 的 live 配置自动指向本地代理，代理按请求模型名（`claude-opus-*` / `claude-haiku-*` 等）分类到对应档位，再把请求以绑定供应商的凭证与格式管线转发出去。支持格式混搭：同一聚合供应商下，opus 档可以走 Anthropic 格式的中转、haiku 档可以走 OpenAI 格式的中转。
- **删除被引用的供应商时心中有数**：删除一个被聚合供应商引用的普通供应商前，会先列出引用它的聚合供应商与档位；确认后非 default 档绑定自动级联清除，default 档引用则会阻止删除（需先编辑聚合供应商）。
- **一眼看清聚合结构**：供应商卡片显示「聚合」徽标与各档来源摘要（如 `opus→A · fable→B · haiku→A`）。

---

## 使用攻略

- **供应商管理**：添加/编辑供应商表单中的聚合模式与档位表格。
- **本地代理**：聚合路由依赖代理接管，切换前请先启动代理服务。
